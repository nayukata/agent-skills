# AI 文章の兆候の点検

日本語の文章から、AI が書いたと読者に見抜かれる兆候を見つけて直す。

## 前提

- 兆候は単体では判定材料にならない。どれだけ多く出るか、ほかの兆候と一緒に出るかで見る。
- 兆候が出る原因は2つある。書き手が持っている情報が足りないか、言うことが無いのに文を埋めたかである。言葉を別の言葉に置き換えるだけでは、兆候が見えなくなるだけで、文章は良くならない。
- 直し方は2つ。具体的な事実 (数値、固有の出来事、コード、観測結果) を書くか、文ごと削る。
- 言葉を置き換えたあとは、文として成り立っているかを読み直す。置き換えただけだと、誰が何をしたのかが抜けた文が残る。

## 点検手順

検出器は Node.js 版 (`.mjs`) と Python 版 (`.py`) があり、候補の行と、Jev に送る文の切り出しは同じになる。手元にある方を使う。Node.js なら `node scripts/check.mjs`、Python なら `python3 scripts/check.py` (Windows では `py scripts\check.py`) のように実行する。どちらも無い環境では、手順1と2を飛ばし、手順2の最後に挙げた観点と兆候の一覧で通読する。

1. `scripts/check.mjs <ファイル>` (または `check.py`) を実行し、候補行と種別ごとの件数を出す。
   - 候補を挙げるだけで、判定はしない。否定の対句と鉤括弧の強調は普通の文でも当たるので、件数が多いときだけ兆候として扱う。否定の対句は 3 件以上のときだけ行を表示する。
   - 複数の文書を同時に出すときは、1 つに連結したファイルにもかける。書き出しの反復は、文書をまたいだときに初めて見える。
2. `scripts/jev_check.mjs <ファイル>` (または `jev_check.py`) を実行し、正規表現で拾えない兆候の候補を出す。TypeSafe の判定 API (Jev) で1文ずつ調べ、確率がしきい値を超えた文だけが出る。この手順は任意で、API キーが無い環境では飛ばしてよい。
   - API キーは、環境変数 `TYPESAFE_API_KEY` か、設定で保存したファイルから読む。キーが無いと、スクリプトは設定コマンドを表示して終わる。利用者が Jev を使いたいなら、そのコマンドを自分で実行する。ブラウザーに入力画面が開くので、TypeSafe への登録からキーの保存までをその画面で進めるよう、利用者に伝える。キーをチャットに貼ってもらわない。キーの値は表示しない。
   - スクリプトは、文と一緒にその段落全体を外部の API へ送る。ファイルに認証情報や個人情報があるなら送らない。
   - 送れないとき、キーが無いとき、実行が失敗したときは、`jev_check` が調べる次の7つの観点で、1文ずつ自分で読む: 主語や立場があいまい (主体が書かれていない)、主語や立場があいまい (途中で入れ替わる)、モノに人の動作をさせる、概念を鉤括弧で強調、名詞に普段付かない動詞を当てる、人が行うことを強調するだけの言葉を付ける、確かめようのないこと・知り得ないことの断定。
3. 全文を通読する。「通読で見る兆候」の表の兆候と、検出器に出なかった兆候を探す。文書どうしでリズムが揃っているかどうかは1文ずつ調べても分からないので、並べて読む。
4. 件数が多い種別から順に、出た行を読む。出た行がすべて兆候とは限らないので、本当に不自然な行だけを、事実を書くか削るかで直す。
5. 否定の対句は、3 件未満で行が表示されなくても、本文を読んで対比に意味があるかを確かめる。
6. 修正した箇所は、置き換え先が新しい兆候になっていないか (大げさな言葉を、別の大げさな言葉に替えていないか) を確認する。直した段落だけを別のファイルに書き出し、1 と 2 をもう一度かける。
7. 直せない行が残ったら、その行が伝えたい事実を書き手 (ユーザー) に聞く。答えを聞くまでは、推測で事実を書かない。

## 兆候の一覧

### 中身の兆候


| 兆候 | 日本語での現れ方 | 直し方 |
| --- | --- | --- |
| 読者が疑っていないことの証明 | 当たり前の動作の確認手順に紙幅を割く | 1 文で流し、つまずきやすい点や意外な事実を中心に書く |
| 手段の誇示 | 「〜を読み込んで調べた」「〜を解析した」と、調べ方を主役にする | 読者が知りたいのは結果。手段は出典として 1 文で触れる |
| 当たり前の前提を主張にする | 誰も疑っていないことを、導入や結論の文にする | 読者がまだ知らない事実から始める |
| 本筋から外れた節 | 主題と関係の薄い注意書きや補足を、節として立てる | 読者の関心が主題にあるなら、節ごと削る |
| 訳と影響の無い引用 | 原文 (英語など) を貼るだけで、意味と「それで何が変わるか」が無い | 引用には訳と、読者にどう影響するかを添える |
| 予告の型 | 何が分かるかを言わない予告 (「この記事では、Git の設定方法を紹介します」)。前置きだけの「結論から言うと」 | 短い文章では削って本題から書く。長い記事で範囲を案内するなら、読者が得るもの (「設定を1行で済ませる方法と、その落とし穴が分かります」) を書く |


### 言い回しの兆候


| 兆候 | 日本語での現れ方 | 直し方 |
| --- | --- | --- |
| 否定の対句 | 「大事なのは速さではなく正確さです」のような「X ではなく Y」「X だけでなく Y も」「X というより Y」を重ねる。読者が思ってもいない誤解を先回りして否定するのも同じ (「この変更は機能追加ではありません」) | 1 つの文書で 2 回までにする。誰も X だと思っていないなら、Y だけを書く |
| 空虚な強調 | 数や程度を言わずに、強めるためだけの言葉を付ける (「言葉は全部すらすら出てきた」の「全部」) | 削るか、比較対象と差を書く |
| 文末の単調 | 「〜です」「〜ます」「〜になります」が段落内で反復する | 体言止め、疑問文、短文で拍を変える |
| 人間が使わない言葉 | ふだん誰も口にしない言葉で書く (「バージョン」で通じるところを「版」と書く)。分野に決まった呼び名があるのに、硬い言い換えを自分で作る | ふだん口にする言い方に戻す。分野に決まった呼び名があれば、その名前で書く |
| 名前だけの説明 | 何を指すか読者に分からない名前を、説明なしに使う | 名前を付けずに「誰が何をするか」を文で書く |
| 直訳の並列 | 原文に並んだ言葉を、そのままの順番と言い回しで訳す | 読者が使う言葉と順番で書き直す |
| 並列の不揃い | 並べた項目の書き方が違う (片方はセリフ、片方は説明) | 同じ書き方に揃える |
| 不要な精度 | 読者の判断に関係ない時点や条件を書く | 判断に関係ない条件は削る |
| 繰り返す属性を毎回文で書く | 節ごとに同じ種類の情報 (対象、条件など) を、毎回文章で書く | ラベル行 (「対象: 〜」) にして、読者が探さずに済むようにする |
| 書き手に見えているものをそのまま書く | 文章の構造 (「この段落」「セクション」「セット」)、内部の仕組み (「フラグで切り替わる」「一覧を見て」)、自分の手順 (「ファイルを読んで調べた」) を、読み手に何が起きるかに言い換えずに書く | 「それは何で、読み手に何が起きるか」で書く (「この自己紹介」「管理者が有効にした時だけ動く」「3つの環境で確認した」)。言い換えられないなら、読み手に要らない情報なので削る |
| 動作を種類の言葉に潰す | 具体的な動作を「一言置く」「〜の形になる」「対応する」のような、動作の種類だけを表す言葉にする | 何を言うのか、何をするのかを動詞で書く (「何をするかを一行で言う」「結論から始まる」)。「形」は物や図の形を指すときだけ使う |
| 主語や立場があいまい | 動作の主体が文に無い。1 文の途中で主語 (書き手、システム、利用者) や視点 (利用者から見た話、運用者から見た話) が断りなく入れ替わる | 動詞ごとに「誰が」を書く。主語や視点が変わるところで文を分ける |
| 概念を鉤括弧で強調 | 引用でも画面の文言でもない言葉を「」で囲んで目立たせる (「新しい」と判定して) | 括弧を外して地の文で書く。鉤括弧は引用と画面の文言に使う |
| 動詞の句を鉤括弧で名詞扱いする | 引用でも画面の文言でもない動詞の句を「」で囲み、名詞のようにすぐ「は」「が」を付ける。「料理は『気持ちを込めて作る』が大事」「『腕を振りかぶって思い切り投げる』はほどほどに」。人はこう言わない | 名詞で言える言葉に替える (「料理は思いやりが大事」「全力投球はほどほどに」)。名詞が無ければ「〜ことが」「〜のは」で受ける。人が実際に言った言葉や画面の文言を引くときの「」は対象外 |
| モノに人の動作をさせる | 情報、設定、画面、ライブラリが「判定する」「待つ」「決める」「丸める」 | 動作の本当の主体 (利用者、書き手、仕組みの名前) を主語にする。主体を書くまでもないなら「〜される」と受け身で書く |
| 同じリズムの繰り返し | 段落が毎回同じ文数と同じ並び (これまで、変えた、結果) になる。どの文も「〜し、〜します」の 2 節で、長さも揃う。複数の文書を同時に出すと、文書どうしでも同じ骨組みになる | 1 節だけの短い文を挟む。段落は、その段落の主役 (原因、判断、結果) から書き始める。同時に出す文書は並べて読み、書き出しと段落の並びを変える |
| 「〇〇の側」「「〇〇」の〇〇は」の構文 | 「私の側では未確認です」「ページの側では確かめられない」のように、名詞に「の側」を付ける。「バックエンド側」「サーバー側」のように「の」を挟まない言い方は、人も普段使うので対象外。「「X」の Y は」と、鉤括弧で囲んだ言葉を主題に立てる | 「の側」を削って読み、意味が変わらなければ削る (「私は確認していません」「ページでは確かめられない」)。鉤括弧で囲んだ言葉を主題にせず、主体と動作で書く |
| 名詞に普段付かない動詞を当てる | 「Cookie を書く」(設定する)、「案内が働く」(表示される、有効になる)、「ボタンを止める」(押せなくする)。文型の重なりを避けるために動詞だけを言い換えると起きる | その名詞とふだん一緒に使う動詞に戻す。文型が重なるときは、動詞は替えずに、主語か文の切り方を変える |
| 人が行うことを強調するだけの言葉を付ける | 「目で確認する」「自分の目で確かめる」「手で直す」。自動の処理と対比したくて、体の部位を使った言葉を付ける。英語の `by eye`、`manually` の直訳でも起きる | その言葉を削って読み、意味が変わらなければ削る (「読んで確認する」「直す」)。「目を通す」「目視確認」「手作業」のように普段から使う言い方は対象外 |
| 仕組みを結果だけに丸める | 「更新時刻の新しいほうを残す」のように、処理の結果を短い言い回しにまとめ、何と何を比べてどうなったら何をするのかが書かれていない | 比べる対象、条件、起きる動作を順に書く (「サーバーのデータのほうが更新時刻が新しければ、端末のキャッシュを上書きする」) |
| 疑問符の無い問いかけ | 台詞が問いの終わり方 (「〜の」「〜よね」「〜だっけ」「何」「なんで」「どこが」「誰が」「〜は」) で終わるのに「？」が無い。「さあって何」のように、問いではなく言い切りの台詞は対象外 | 問いかけには「？」を付ける。言い切りなら、問いに読めない終わり方にする |
| 逆接の「のに」の後に依頼・勧誘 | 「〜なのに、〜してください」「〜のに、〜しよう」。「のに」は予想と食い違う事実を受けるので、依頼・勧誘とつながらない | 「〜だけど、〜してください」のように、逆接をゆるい接続に替える。逆接が要らなければ削る |
| 確かめようのないことの断定 | 語り手がその場で確かめられない他人の内心や、遠くの人の素性を、事実として言い切る。当時も知らなかったことを「覚えていない」と書くのも同じ。推量を根拠なく言い切る (「AI は新しい発想が苦手です」)。確認していないことを確認したように書く (確かめずに「既知の問題です」と書く) | 見聞きしたことと推測を分け、推測は「らしい」「のかもしれない」で書く。当時知らなかったことは「知らない」と書く。言い切りたいなら根拠を書く。根拠が無ければ「〜と考えている」「〜のようだ」と推定だと分かる書き方にする。確かめようがないなら削る。作中人物の認識や読者の疑念を表す推量は、断定に直さない |


### 通読で見る兆候

次の兆候には検出器が無い。


| 兆候 | 日本語での現れ方 | 直し方 |
| --- | --- | --- |
| すぐ後の文と食い違う言い切り | 「思ったのはそれだけだった。」と書いた直後の文で、胸が落ちた感覚など、それ以外に起きたことを書く | 言い切りを外すか、後の文と矛盾しない範囲に狭める |
| 主語と述語のねじれ | 「書道を習っている字は、クラスで私だけだった」。習うのは人なのに、字が主語になっている | 述語に合う主語に戻す (「クラスで書道を習っているのは、私だけだった」) |
| 指示語や呼び名が別のものを指して読める | 直前に別の候補があるのに「それ」と書く。直前の台詞で語り手が「先輩」と呼ばれた直後に、別の人を「先輩」と書く | 指すものを名詞で書く (「端から食べるのは」「部活の先輩は」) |
| 原因になっていないことを原因として書く | 「AなのでB」の A が、B の直接の原因ではない。途中が飛んでいるので、読み手は「なぜ A だと B になるのか」と引っかかる (「キャッシュが古いので、画面が崩れます」。崩れる直接の原因は、古い CSS が新しい画面の部品と合わないこと) | 直接の原因を書く (「古い CSS が残っていて新しい画面の部品と合わないので、表示が崩れます」) |
| 内容の分からない見出し | 「結論」「まとめ」「補足」のような種別名だけの見出し。「数えた結果」「直した後」のような手順だけの見出し。PR のひな形などで決まっている構成の見出し (「概要」「背景」「変更内容」「動作確認」) は対象外 | その節が答える問いか、扱う対象を見出しにする |
| 読みが割れて意味が変わる漢字 | 「十分黙っていた」(じゅっぷん／じゅうぶん)。前後を読んでも読みが決まらない | 意味が決まる書き方にする (「十分間」「十分に」) |


### 書式の兆候


| 兆候 | 直し方 |
| --- | --- |
| 太字の乱用 (表以外の 1 行に 2 か所以上) | 太字が多いと、どれも目立たなくなる。初めて出てきて意味を説明する言葉だけに絞る |
| PR 本文や記事の地の文で、「**見出し**: 説明」形式の箇条書きが 3 行以上続く | 用語の定義の列挙ならそのまま。それ以外は文でつなぐ。作業報告の箇条書きでは使ってよい |
| 見出しの直下に本文が無く、すぐ次の見出しが続く (「## 設定の手順」の直下に、すぐ「### インストール」が来る) | 見出しを削るか、その見出しの問いに答える本文を書く |
| 表にする必要の無い内容の表 | 比較・数値・状態以外は箇条書きか地の文にする |
