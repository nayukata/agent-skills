# Web Marketing

集客の失敗の多くは、施策の選び方より前で起きる。「誰に・何を・なぜ信じてもらうか」が曖昧なまま、あるいは詰まっている場所と違う場所に手を打って消耗する。
このスキルは、マーケティングの知識がないユーザーから戦略を引き出し、ボトルネックの特定 → チャネル選定 → 施策 → 計測まで翻訳する。

## 原則

1. **戦術の前に戦略**。「Instagramやるべき？」に直接答えない。誰に何を届けるかと、どこが詰まっているかが先。
2. **マーケ用語をユーザーに持ち込まない**。質問は日常語で行い（「お客さん、今はどこから来てる？」）、フレームワークへの翻訳はこちらの仕事。報告も日常語で返す。
3. **言われなかったことは仮説で埋め、仮説は隠さない**。仮埋めしたブリーフを見せて訂正の機会を渡す。
4. **全部やらない**。チャネルは「ターゲットがいる場所 × 続けられるリソース」で1〜2個に絞る。中途半端な5チャネルより継続できる1チャネル。
5. **ボトルネック以外に手を出さない**。認知が足りないのにサイトを磨かない。行動されないのにフォロワーを増やさない。
6. **施策はスタートであってゴールではない**。計測と改善の設計までがマーケティング。

## フロー

チェックリストで進捗を管理する（タスク管理ツールでも応答本文への記載でもよい）:

```
- [ ] 1. マーケティングブリーフ仮埋め
- [ ] 2. ファネル診断（どこで詰まっているか）
- [ ] 3. チャネル選定
- [ ] 4. 施策への翻訳
- [ ] 5. 計測・改善設計
```

### 1. マーケティングブリーフ仮埋め

依頼が手段の形で来たら（「フォロワーを増やしたい」「広告を出したい」「SEOをやりたい」）、まずビジネスのゴールに言い換えて見せてからブリーフに入る。手段の是非はステップ3まで保留する。
[references/brief.md](references/brief.md) のテンプレートを、依頼文と手持ち情報から全項目仮埋めして見せる。
推測した項目には（仮）を付け、「違うところだけ教えて」と渡す。
割れやすい論点（ターゲット、ゴール）は、表を見せたのと同じターンで1回の AskUserQuestion にまとめて聞く（2問程度まで）。表の他の項目の訂正は、選択肢の「その他」欄や次のやり取りで自由記述として受ける。

### 2. ファネル診断

[references/funnel.md](references/funnel.md) を参照し、「客が増えない」をどの段階の詰まりか特定する。
数字がなくても止まらない。ユーザーへの日常語の質問と仮説で暫定判定し、前提を明示して進む。

### 3. チャネル選定

[references/channels.md](references/channels.md) の一覧表を参照し、ボトルネックの段階に効くチャネルを、ターゲットの居場所とリソースで絞る。
候補が割れたら AskUserQuestion で選択肢にする（各選択肢に必要リソースと効くまでの時間を添える）。
すでに運用中のチャネルがあるなら、新チャネル追加より先に既存の改善を検討する。

### 4. 施策への翻訳

選んだチャネルの具体施策に落とす。
- SNS運用 → [references/sns.md](references/sns.md)
- LP の制作・改善 → lp-marketing スキルに接続する（無ければ [references/channels.md](references/channels.md) の広告・LPの項で代用）
- SEO・コンテンツ、広告、メール/LINE → [references/channels.md](references/channels.md) の該当チャネルの「最初の一歩」に従う
施策は「今週から何をするか」のレベルまで具体化して見せる。

### 5. 計測・改善設計

[references/measurement.md](references/measurement.md) を参照し、ボトルネックに対応した「見る数字」を1〜2個決めてユーザーに引き継ぐ。
振り返りの周期（週次で見る・月次で判断・3ヶ月でチャネル継続判断）も合わせて渡す。

## 「なんとなく集客したい」という相談のとき

目的が曖昧なのも正規の入力として扱う。言語化をユーザーに求めない。
1. ビジネスのゴールから逆算した仮ゴールを数字で置いて見せる（「月の問い合わせ+5件、という理解で合ってる？」）
2. あとは通常フローに乗せる
